# 自学习判定模型 · 设计

## 现状为什么不会学

今天的判定链是一个**冻结的产物**：

```
data/baseline/model.json  ← 我离线跑 scripts/baseline/train.ts 生成
CURATED_HARD_BAN          ← 我手写在 score.ts 里
```

每漏一个账号，路径都是：你截图 → 我改 TypeScript → 重新构建 → 你 reload。
今天一天已经走了五轮。模型本身没有任何反馈入口，你手动拉黑的 5000 条样本
躺在 `chrome.storage` 里，除非我手工导出重训，否则一条都不参与判定。

## 设计的第一原则：学习只能扩大「送审」，不能直接扩大「定罪」

这是整套设计的支点。

你反复强调的红线是**不能误杀**。但自动学习天然会产出过泛的规则 —— 上一轮
「同城」差点被挖成定罪词就是例子。既要学，又不能误杀，唯一的解法是把
**「什么触发关注」和「什么导致封禁」拆成两级**：

| 层级 | 规则命中后 | 学错的代价 |
|---|---|---|
| **候选**（candidate） | `decision = llm` → 交大模型判 | 一次 API 调用。大模型说 legit 就放行，**没有误杀** |
| **可信**（trusted） | `decision = ban` → 直接拉黑 | 误杀 |
| **退役**（retired） | 永不触发 | 无 |

新学到的规则**一律进候选层**。候选层可以放心地激进 —— 最坏结果是多花几分钱。
只有攒够证据才升级到可信层。这样「学习」这件事结构上无法制造误杀。

## 四个循环

### 循环 1 · 蒸馏：手动拉黑 → 候选规则

你每次手动拉黑，把那条样本交给大模型，让它回答一个很窄的问题：
**「这个账号身上，哪个片段是可复用到同类账号的？」**

输出是**受约束的语法**，不是自由文本，更不是自由正则：

```json
{ "signatures": [
    { "kind": "phrase",   "field": "name", "value": "返佣" },
    { "kind": "cooccur",  "field": "tweet", "all": ["主页", "私信"] },
    { "kind": "structure","id": "at_redirect_bait" }
] }
```

- `phrase` / `cooccur` —— 可学习的两种形态
- `structure` —— 只能**引用**已有的手写结构检测器（@导流诱饵等），不能凭空发明

不给大模型写正则的权力。它能提议「哪些字符串重要」，不能提议「怎么匹配」。

### 循环 1b · 留存原文模板（不经过 AI）

蒸馏依赖 AI，而 AI 有权回答「这个号身上没有可复用的特征」。真实案例：

```
30+的cb体制内老师 已探路花样多 @tiagolvr7 1s
30+的al体制内老师 玩的就是返差 @Hop4Toy 9r
```

同一批号，但没有任何一个词能单独定性 —— 抽关键词这条路在这里是走不通的。
不变的是那段一字不差的共同前缀。

所以每次手动拉黑**同时**留一条整句模板，纯本地、不联网：

- **先剥噪声**：@跳转目标、1-3 字母的随机填充（cb / al / mt）、链接。
  不剥的话同一对样本相似度从 0.50 掉到 0.09 —— 剥噪声不是优化，是前提。
- **相似度取两种度量的大者**：最长公共子串率覆盖「固定开头 + 随机尾巴」，
  词片重合度覆盖「同批词换个说法」。上面那对样本 Jaccard 只有 0.27，
  LCS 率 0.50 —— 只用 Jaccard 就会整类漏掉。
- **两档阈值**：≥0.45 直接处理，≥0.30 送 AI 复核。两档都可在面板上调。

实测余量：目标变体 0.50，该模板 vs 15 条正常中文推文最高 0.19，
正常 vs 正常最高 0.17。另有一条**绝对**门槛：公共子串至少 6 个字
（正常推文之间最高只有 3 个字）。

模板规则直接以**可信**层入库，与 AI 蒸馏出的短语不同。理由是证据等级：
短语是 AI 的推断，模板是用户亲手判过的那条原文本身，一个字都没改。
相似度阈值是它的安全边际，取代了短语靠 8 次确认换来的那份把握。

### 循环 2 · 准入体检：候选规则落库前的五道闸

蒸馏出来的每条候选，在写进库之前本地跑五个纯函数检查（不花钱、不联网）：

1. 归一化后长度 ≥ 3 汉字 / ≥ 5 拉丁字符
2. 不在 `never_approve` 名单里（同城 / 线下 / 主页 / 简介 / 资源 / 进群 …）
3. **不匹配任何一条已存的 legit 负样本**
4. **不匹配公开白名单里 2023 个已知正常账号**
5. 与已有规则去重（互为子串时留信息量更大的那条）

第 3、4 条是机器版的「同城否决」。它不靠我判断词泛不泛，靠**拿正常账号去打**：
任何一条会打到已知好人的规则，当场毙掉。这比人工 review 更可靠，而且随着你
积累负样本会越来越严。

### 循环 3 · 晋升与退役：靠实战数据决定谁能定罪

```
候选规则命中 → 送大模型 → 记一次战绩
   大模型判 spam  → hits+1
   大模型判 legit → 当场退役（这条规则打到了好人）
   你点「恢复显示」→ 当场退役 + 该样本进负样本库
```

晋升到可信层（自动定罪）的条件全部满足才行：

- 命中过 **≥ 8 个互不相同的账号**
- 大模型判定 **100% 是 spam**，一次 legit 都没有
- **零**用户恢复
- 通过一次全量负样本回扫

退役是**即时**的，且会**回溯**：一条新负样本入库时，会拿它去扫全部现存规则
（候选 + 可信），凡是打中的一律退役。所以你每纠错一次，模型不只是改了那一个
账号，是把整类误判源头拔掉。

管理面板里可以手动升/降级 —— 你说了算永远优先于计数。

### 循环 4 · 通审：真正意义上的「让大模型优化模型」

在「模型学习」页点「开始通审」，把**当前全部学到的规则 + 战绩统计 + 全部
负样本**一次性喂给大模型，让它做三件事：

- 合并重叠规则（`没我骚` / `没她骚` / `没我Sao` → 一条带人称变体的）
- 针对负样本收紧过宽的规则（自动生成 `not:` 例外表，就像 `看福` → `看福建`）
- 指出规则库的**盲区**：哪些负样本本该被某条规则打到却没有

输出是一份**提案**，逐条等你点「采纳」，**绝不自动生效**。
这是全流程里唯一能大范围改动定罪行为的地方，必须过人 —— 也正因为必须过人，
它做成手动触发而不是定时任务：一份没人看的提案既改不了什么，又在烧钱。

## 大模型配置搬到扩展设置页

现在 base / key / model 是构建期 `.env` 注入的，改一次要重新构建。
设置页加一个「AI 判定」区块：

- 接口地址 / API Key / 模型名 / 开关
- 「测试连接」按钮（发一条固定样本，回显判定结果与耗时）
- 用量计数：今日调用次数、蒸馏次数、平均延迟

存 `chrome.storage.local`，background 每次读取。`.env` 降级为首次安装的默认值。

## 完整判定链（改造后）

```
1. 白名单                        → pass
2. 人工点名短语 / 挖掘 T1 短语    → ban
3. 昵称模板簇 / 推文模板簇        → ban
4. 结构检测器（@导流诱饵）        → ban
5. ★ 学到的可信规则               → ban
6. ★ 学到的候选规则               → llm
7. 加权信号 ≥ 2                   → llm
8. 其余                          → pass

   llm → 大模型判定 → ban / pass
        └→ 回写规则战绩、晋升/退役
   手动拉黑 → ★ 蒸馏出新候选规则
   手动恢复 → ★ 退役肇事规则 + 全量回扫
```

★ 是新增部分。前四条完全不动 —— 现有的高精度路径不受学习影响。

## 什么**不**做自学习

昵称簇 / 推文簇模型不动。它们需要十万级语料做跨簇统计，扩展本地几千条样本
做不出来，硬做只会得到「伪模板」。这部分仍然离线重训，用你积累的样本当增量
语料。学习和重训是互补的，不是替代。

## 同期做的减法

公榜与官方关键词规则两条来源移除后，它们专属的门禁失去了服务对象，一并删掉：

- 「自动处理范围」(`autoScope`)：曾用来把规则命中限制在评论区
- 「自动收录条目」(`autoTierMode`)：曾用来给非人工确认的公榜条目封顶
- 分类别动作网格：六个类别各自一档，实际使用中从没被分开调过

`categoryActions` 数据结构保留（判定链仍按类别走），UI 收成一个统一的
「命中后的动作」，默认 X 拉黑。`autoEligible` 从五个分支收成一句话。
