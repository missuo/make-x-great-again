# Baseline 模型

从公榜正样本训出的判定基线。目标不是「尽可能多地封人」，而是**在结构性高精度的地方定罪，其余一律不表态**——漏掉的账号可以靠上报补回来，误杀一个正常人是不可逆的。

## 为什么不是一个普通的二分类器

我们没有负样本。白名单只有 2,023 条且不含 `display_name`，公开接口也不返回。更关键的是**标签本身是脏的**：最近 5 万条公榜条目里 20,274 条（40.5%）是纯关键词命中、无任何 AI 复核，其中 13,834 条由泛化词单独产生：

| 旧规则 | 命中账号 | 问题 |
|---|---|---|
| `同城` | 6,487 | 单个词，同城交友/本地商家全中 |
| `vpn` | 1,486 | 证据文本是正常的行业讨论推文 |
| `主页` / `简介` / `资源` / `线下` | 2,169 | 中文最常见的词 |
| `应该没人` / `比我好看` / `太涩了` | 1,253 | 正常人日常用语 |
| `visa` / `高返` / `bitget` / `weex` | 2,343 | 币圈正常账号必然命中 |

拿这批标签去训判别式模型，只会把「同城 = spam」从一条可审计、可撤销的规则，固化成一组不可解释的权重——误杀会更隐蔽，且再也撤不回来。

所以 baseline 学的是另一个问题：**这个账号是否属于一个被大量复用的批量模板**。这个问题纯正样本自己就能回答，而且高精度是结构性的——定罪需要整名匹配上模板或命中经签字的高频短语，不是命中一个碎片词。

## 三条定罪路径（且仅此三条）

| # | 路径 | 门槛 | 主观性 |
|---|---|---|---|
| 1 | 人工点名短语命中昵称/简介 | 见 `src/baseline/score.ts` 的 `CURATED_HARD_BAN` | 维护者担责，明确标注 |
| 2 | T1 短语命中昵称/简介 | 经维护者签字（计数门槛只用于推荐审阅范围） | 一次性签字，全部可审计 |
| 3 | 昵称整名匹配批量模板 | 与簇代表点 Jaccard ≥0.6，簇规模 ≥20 账号，昵称 ≥8 字符 | 纯计数 |

其余信号（handle 形态、账号年龄、默认头像、装饰 emoji、T2 短语）**只加权，永不单独定罪**。加权分 ≥2 送 LLM，否则彻底放行、不消耗 LLM 预算。

### 为什么短语要签字

计数选不出语境。`点击主页`（17,612 账号 / 27 簇）与 `同城上门`（37,769 账号 / 273 簇）的统计特征几乎一致，机器无从区分。但在中文 X 的实际语境里，`点击主页` / `查看主页简介` / `真实约见` 这一类导流话术**就是**色情招揽的固定说法 —— 这是领域知识，只有人能判断。

所以计数门槛只用来**推荐审阅范围**，不限制授权范围：任何被挖掘出的短语都可以写进 `data/baseline/approved-phrases.json` 的 `approved` 数组，签字后即刻生效。这把主观判断压缩到一份一眼能看完的文件，而不是散落在 20 万条记录里的逐条决定。git history 即审计日志。

文件里另有一份 `never_approve`：旧规则集里真实存在过、合计误伤 13,834 个账号的泛化词（`同城` / `线下` / `主页` / `vpn` …）。它们全部短于挖掘的最小长度，结构上挖不出来；列在那里是为了留下记录，并由 `test/baseline.test.ts` 强制——任何一条重新获得定罪能力，测试就会失败。

训练脚本还会报告**孤儿条目**：签了字但本轮未被挖出的短语。没有这个告警，一条授权可能因为数据变化静默失效。

### 两道结构护栏

- **昵称长度 ≥8**：没有它，`博博` / `CDCO` / `硅谷居士` / `ERIC` 这类被十几个账号共用的短名字会被当成「模板」——短名字本来就会被不相干的真人共用，按它封人就是按名字封人。维护者已确认这些都是正常账号，`test/baseline.test.ts` 用真实模型逐个验证它们不被定罪。
- **簇规模 ≥20 账号**：8 个字符以上的昵称被 20 个以上账号逐字复用，只可能是批量生产。

### 归一化是前提

公榜数据里可以直接观察到形近字规避：`上→丄`、`门→椚`、`炮→萢`、`处→chu`、`约炮→曰p`。不做归一化的短语表配好当天就会被绕过。归一化实现唯一存放在 `src/baseline/normalize.ts`，训练与推理共用——各存一份副本迟早分叉，而分叉会静默地让模型失效。

## 指标

训练集：`/v1/list` 全量拉取的 196,072 条带 `display_name` 条目。

**覆盖率**

| 判定 | 条数 | 占比 |
|---|---|---|
| 直接定罪 | 132,557 | 67.6% |
| 送 LLM | 3,309 | 1.7% |
| 放行（不表态） | 60,206 | 30.7% |

**假阳性**（测试集 = 公榜里 AI 自己判为 `legit`/`uncertain` 的 1,917 条，即已知误杀嫌疑样本）

仍被定罪 18 条（0.9%）。逐条核对后**这 18 条全部是真阳**（`chu男无偿`、`ALLISON♥同城无偿💘`、`全国1-5线真实约见入口点我`）——是当初的 AI 标签错了，不是 baseline 错。

**handle 形态分类器**（唯一有真实负样本的部分：黑名单 handle vs 白名单 2,023 个 handle，留出 20%）

| 指标 | 值 |
|---|---|
| AUC | 0.905 |
| 最佳准确率 | 83.3% |
| 该阈值下白名单假阳 | **72 / 405（17.8%）** |
| 零假阳阈值下召回 | 3.2% |

这组数字就是「handle 形态永不单独定罪」的依据：想要零误杀就只剩 3.2% 召回，想要高召回就得接受 17.8% 的正常账号被误封。它只配当一个加权信号。

## 用法

```bash
# 训练（输入是 /v1/list 全量导出的 jsonl，每行一条）
npm run baseline:train -- <input.jsonl> data/baseline/model.json

# 验收：覆盖率 + 假阳性 + 清洗口径预演
npm run baseline:eval -- <input.jsonl> data/baseline/model.json

# 回归测试：锁死「泛化词永不定罪」等红线
npm test
```

新一轮训练若挖出新的高频短语，会打印「推荐审阅的候选」并**默认不授予定罪权限**，审阅后加进 `approved-phrases.json` 才生效；反过来，签了字却没被挖出的短语会以「孤儿条目」告警报出，避免授权静默失效。

## 后续

1. **LLM 兜底**：`decision === "llm"` 的 1.7% 交给大模型判定
2. **全量 review 队列**：LLM 每条输出都进后台待审，不再直接发布（现状是规则/AI 命中直接写 `human_confirmed`，绕过队列）
3. **上报补回**：baseline 主动放过的 30.7% 靠上报机制回收——宁可漏，不可误杀
4. **升级判别式模型**：等 review 队列攒出足够的人审正负样本，再训字符 n-gram 逻辑回归（可在扩展本地跑，零上传）。届时训练标签是人审过的，不是坏规则生成的。
